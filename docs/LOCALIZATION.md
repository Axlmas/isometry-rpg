# Локализация

Все тексты, которые видит игрок, лежат в каталоге переводов. В коде и HTML — только ключи.

## Языки

| Код | Язык | Статус |
|---|---|---|
| `en` | English | Исходный и запасной язык |
| `ru` | Русский | Поддерживается |
| `en-XA` | Псевдолокаль | Только для проверки вёрстки, игроку не предлагается |

Язык выбирается так: сохранённый выбор игрока → языки браузера → `en`. Игрок меняет язык
кнопкой в игре, выбор запоминается на устройстве.

## Файлы

| Путь | Что там |
|---|---|
| `src/i18n/locales/en.json` | Исходные тексты. Источник истины для списка ключей |
| `src/i18n/locales/ru.json` | Русский перевод |
| `src/i18n/locales/_notes.json` | Пояснения для переводчика по ключам |
| `src/i18n/index.ts` | Список языков, выбор языка, функция `t()` |
| `src/i18n/pseudo.ts` | Генерация псевдолокали |
| `scripts/check-i18n.mjs` | Проверка каталога |

## Правила

- **Ключи:** `раздел.имя` в camelCase, например `hud.newDungeon`, `confirm.newDungeon.yes`.
  Раздел — место в интерфейсе (`hud`, `quick`, `skills`, `inventory`, `shop`, `log`, `prompt`, `toast`, `death`,
  `error`) или вид данных (`item`, `slot`, `grade`, `skill`, `skillInfo`, `zone`), не тип элемента.
  Ключ описывает смысл, а не текст.
- **В коде** ключ всегда пишется строковым литералом: `i18n.t('hud.hint')`,
  `hud.toast('toast.saveDamaged')`, в HTML — `data-i18n="hud.hint"`. Собирать ключ из
  частей нельзя: проверка его не найдёт.
- **Формат сообщений — ICU MessageFormat.** Подстановки: `{language}`. Числа и формы
  множественного числа: `{count, plural, one {# шаг} few {# шага} many {# шагов} other {# шага}}`.
  Нужны все формы, которые есть в языке (в русском — `one`, `few`, `many`, `other`).
  Не склеивайте предложения из кусков: порядок слов в языках разный.
- **Числа, даты, валюта** форматируются по правилам языка самим ICU (`#`, `{n, number}`,
  `{d, date}`), вручную их не форматируем.
- **Названия предметов, слотов, грейдов и умений.** Правила знают только ID. Ключ по ID
  берётся из таблиц в `src/client/itemText.ts` (`ITEM_NAME`, `SLOT_NAME`, `GRADE_NAME`)
  и `src/client/skillText.ts` (`SKILL_NAME`, `SKILL_INFO`), названия зон —
  в `src/client/zoneText.ts` (`ZONE_NAME`), где он
  записан целиком: `ironSword: 'item.ironSword'`. Названия предметов — в словарной форме;
  фразы вокруг них строятся так, чтобы эта форма подходила («Подобрано: Железный меч»).
- **Названия языков** в переключателе (`English`, `Русский`) не переводятся и лежат в
  `LOCALES` в `src/i18n/index.ts`.
- **Правила игры и сейвы** не содержат текстов: только ID и числа. Если правилам нужно
  что-то сообщить игроку, они возвращают код, а клиент выбирает по нему ключ.

## Поведение при проблемах

- Ключа нет в текущем языке или перевод сломан → показывается английский текст,
  в консоль пишется предупреждение.
- Ключа нет и в английском → игрок видит `…`, в консоль пишется предупреждение.
  До игрока это дойти не должно: `npm run i18n:check` ловит такое до публикации.
- Ключи, коды и тексты ошибок игроку не показываются никогда.

## Команды

```bash
npm run i18n:check
```

Проверяет: во всех языках один и тот же набор ключей; каждое сообщение — корректный ICU
с теми же подстановками, что в английском; каждый ключ из кода существует; нет
неиспользуемых ключей; заметки переводчика ссылаются на существующие ключи.

```bash
npm test
```

Среди прочего: каждое сообщение форматируется в каждом языке и в псевдолокали, формы
множественного числа, запасной язык, выбор языка.

Проверка вёрстки на длинных текстах: открыть игру с `?pseudo` в адресе. Тексты станут
примерно на 40% длиннее и с диакритикой: `[Ñéŵ đüñĝéöñ ~~~~]`. Обычный текст без
скобок на таком экране — строка, не попавшая в каталог.

## Как добавить текст

1. Добавить ключ в `en.json` и во все остальные языки.
2. Если смысл неочевиден без контекста — заметку в `_notes.json`.
3. Использовать ключ в коде.
4. `npm run check`.

## Как добавить язык

1. Скопировать `en.json` в `<код>.json` и перевести значения (ключи не менять).
2. В `src/i18n/index.ts`: импортировать файл, добавить в `RESOURCES` и в `LOCALES`
   (собственное название языка и направление письма `ltr` или `rtl`).
3. `npm run check`, затем открыть игру на этом языке на телефоне и ПК.
4. Проверить, что системный шрифт содержит нужные символы; если нет — добавить шрифт
   в `font-family` в `src/client/style.css` и описать источник в `docs/ASSETS.md`.

Обновление перевода — правка значений в `<код>.json` и `npm run i18n:check`.

Ответственность: исходные тексты (`en.json`) и список ключей ведёт тот, кто делает
фичу; переводы — владелец проекта или переводчик, которого он назначит.

## Что заложено, но не проверено

Поддержку этих вещей заявлять нельзя, пока не появится соответствующий язык и проверка:

- **Письмо справа налево (арабский, иврит).** `dir` выставляется из `LOCALES`, стили HUD
  используют логические свойства (`inline`, `block`, `start`). Ни одного RTL-языка нет,
  на RTL игра не проверялась.
- **Китайский, японский, корейский.** Шрифты берутся из системы; переносы строк и набор
  символов не проверялись.
- **Ввод текста и IME.** Игрок пока нигде не вводит текст.
- **Текст на игровом холсте.** Внутри Phaser рисуются только цифры урона; они
  форматируются через `Intl.NumberFormat` для текущего языка. Весь остальной текст —
  HTML поверх игры. Если на холсте появятся слова (имена, реплики), для них нужно
  отдельно решать шрифты и RTL.
- **Субтитры, озвучка, локализованные картинки.** Звука и ассетов с текстом нет.
- **Скриншоты по языкам в CI.** Не настроены; сейчас вёрстка проверяется вручную.
