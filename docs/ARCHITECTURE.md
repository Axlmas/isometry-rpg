# Архитектура

Одиночная браузерная игра без сервера. Весь код — TypeScript, сборка — Vite,
отрисовка — Phaser 3.

## Слои

```
src/sim/      правила игры           не знает о браузере и графике
src/client/   отрисовка, ввод, HUD   читает мир, меняет его только командами
src/i18n/     тексты для игрока      не знает о правилах
```

Зависимости идут в одну сторону: `client` → `sim`, `client` → `i18n`. `sim` не
импортирует ничего, кроме самого себя.

### `src/sim` — правила

| Файл | Что делает |
|---|---|
| `rng.ts` | Генератор случайных чисел с seed (mulberry32) |
| `grid.ts` | Карта из тайлов: пол и стены |
| `collision.ts` | Столкновения круга со стенами: помещается ли, выталкивание, прямая видимость |
| `pathfinding.ts` | Обход стен: кратчайший путь по тайлам, 8 направлений без срезания углов |
| `world.ts` | Состояние мира, создание комнаты, `step()` |

Ключевые решения:

- **Фиксированный шаг.** Мир движется тиками по 50 мс (`TICK_MS`). Результат не зависит
  от частоты кадров устройства.
- **Детерминизм.** `createWorld(seed)` и последовательность команд полностью определяют
  результат. Поэтому в `sim` запрещены `Math.random`, `Date` и любые обращения к браузеру.
  Это проверяет тест «replays identically» и сборка `tsconfig.sim.json` без DOM.
- **Команды.** Единственный способ изменить мир извне — `step(world, commands)`. Команды:
  `moveTo` (идти в точку, обходя стены) и `moveDir` (идти в направлении, пока оно зажато;
  нулевой вектор — остановка). Последняя команда отменяет предыдущую. Невозможные команды
  (стена, точка вне карты, не число) игнорируются; направление нормализуется в правилах,
  поэтому никакой ввод не даёт скорость выше `PLAYER_SPEED`.
- **Свободное перемещение.** Герой — круг радиусом `PLAYER_RADIUS` (0,3 тайла) с дробными
  координатами, к сетке не привязан. Стены остаются тайлами. При движении в стену круг
  выталкивается наружу, поэтому герой скользит вдоль стены, а не застревает.
- **Маршрут по клику.** Сетка используется только чтобы найти обход стен. Затем лишние
  точки выбрасываются (до каждой следующей герой идёт по прямой, если она свободна), а
  конечная точка — ровно место клика, отодвинутое от стены, если герой там не помещается.

Зачем так: правила тестируются без браузера, а если позже понадобится сервер (облачные
сохранения, рейтинги), он сможет запускать тот же код и перепроверять результат.

### `src/client` — клиент

| Файл | Что делает |
|---|---|
| `main.ts` | Точка входа: собирает язык, сохранение, HUD и сцену |
| `DungeonScene.ts` | Рисует мир, превращает клавиши, клики и касания в команды, крутит тики |
| `iso.ts` | Перевод координат тайл ↔ экран |
| `hud.ts` | HTML-слой поверх игры: тексты, кнопки, диалог, ошибки |
| `save.ts` | Сохранение и загрузка, выбор языка |
| `style.css` | Стили HUD |

Сцена рисует положение героя между двумя последними тиками (интерполяция), поэтому
движение плавное при любой частоте кадров. Время между кадрами берётся из
`performance.now()`, а не из Phaser: тот сглаживает и обрезает свою дельту, и на
устройствах с неровной частотой кадров игра шла медленнее.

Управление:

| Ввод | Действие |
|---|---|
| WASD или стрелки | Идти в направлении на экране, пока клавиша зажата. Клавиши читаются по физическому положению (`KeyboardEvent.code`), раскладка не важна |
| Клик или касание | Идти в эту точку |
| Удержание кнопки мыши или пальца | Идти за указателем |

Пока открыт диалог, клавиши движения не действуют.

### Сохранение

- Хранится в `localStorage` браузера, на этом устройстве. Ключи: `isometry-rpg.save`,
  `isometry-rpg.locale`.
- Формат (версия 2): `{ version, seed, x, y, distance }`, координаты дробные. Карта не
  хранится, она восстанавливается из seed.
- Сохраняется, когда герой остановился, при создании нового подземелья и при закрытии
  страницы.
- Сейв считается недоверенным вводом: каждое поле проверяется. Повреждённый или
  устаревший сейв не ломает игру — начинается новое подземелье, игрок видит сообщение.
- При изменении формата: увеличить `SAVE_VERSION` и добавить шаг в `migrate()` в
  `save.ts`. Сейчас есть миграция 1 → 2. Сейв неизвестной версии считается повреждённым.

### Что видит игрок при сбоях

| Ситуация | Поведение |
|---|---|
| Сейв не читается | Новое подземелье и уведомление |
| Браузер запретил хранилище или оно переполнено | Игра работает, в HUD предупреждение, что прогресс не сохранится |
| Необработанная ошибка в коде | Экран «Что-то пошло не так» с кнопкой перезагрузки; детали в консоли |
| Отключён JavaScript | Статичное сообщение на двух языках |

## Проверки

| Команда | Что проверяет |
|---|---|
| `npm run typecheck` | Типы; отдельно — что `src/sim` собирается без DOM |
| `npm test` | Тесты в `tests/` (Vitest): правила, сохранение, локализация |
| `npm run i18n:check` | Каталог переводов (см. `LOCALIZATION.md`) |
| `npm run build` | Сборка в `dist/` |
| `npm run check` | Всё перечисленное подряд; то же запускает CI |

Автоматических браузерных (end-to-end) тестов в репозитории пока нет: этап 1 проверялся
в браузере разовым скриптом Playwright (клавиши, клик, удержание, касание, сохранение). Их стоит добавить, когда появится бой.

## Как расширять

- **Новое правило** (урон, лут, опыт): состояние — в `World`, логика — в `step()` или
  в функции, которую он вызывает, новая команда — в тип `Command`. Сначала тест в
  `tests/sim.test.ts`.
- **Новый объект на экране**: рисуется в `DungeonScene` по данным из `World`.
  Глубина отрисовки — `x + y` в координатах мира.
- **Новый текст**: см. `LOCALIZATION.md`.
- **Новые данные в сейве**: поле в `SaveData`, проверка в `parseSave`, тест, новая версия.

## Известные ограничения

- Одна комната 18×18, врагов и предметов нет.
- Графика временная (фигуры), на экранах с высокой плотностью пикселей слегка размыта.
- Сейв привязан к браузеру и устройству; очистка данных сайта его удаляет.
- У превью каждой ветки общий `localStorage` с основной версией (один домен), поэтому
  сейвы разных веток перезаписывают друг друга.
- Phaser даёт ~330 КБ (gzip) на первую загрузку.
