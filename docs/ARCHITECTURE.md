# Архитектура

Одиночная браузерная игра для ПК (мышь и клавиатура) без сервера. Весь код — TypeScript, сборка — Vite,
отрисовка — Phaser 3.

## Слои

```
src/sim/      правила игры           не знает о браузере и графике
src/client/   отрисовка, ввод, HUD   читает мир, меняет его только командами
src/i18n/     тексты для игрока      не знает о правилах
```

Зависимости идут в одну сторону: `client` → `sim`, `client` → `i18n`. `sim` не
импортирует ничего, кроме самого себя.

### `src/sim` — правила

| Файл | Что делает |
|---|---|
| `balance.ts` | Все настраиваемые числа: скорости, здоровье, урон, дальности, задержки |
| `rng.ts` | Генератор случайных чисел с seed (mulberry32) |
| `grid.ts` | Карта из тайлов: пол и стены |
| `collision.ts` | Столкновения круга со стенами: помещается ли, выталкивание, прямая видимость |
| `pathfinding.ts` | Обход стен: A* по тайлам, 8 направлений без срезания углов, с ограничением на число просмотренных клеток |
| `zones.ts` | Две карты (открытый мир и подземелье), регионы открытого мира, выходы, расстановка монстров |
| `world.ts` | Типы состояния (`World`, `Player`, `Monster`), команды, события, создание зоны |
| `step.ts` | `step()`: один тик мира — команды, движение героя, удар, восстановление здоровья |
| `combat.ts` | Попадание удара героя, поведение монстров (погоня, возврат домой, возрождение), урон по герою, выпадение добычи |
| `classes.ts` | Расы и классы: множители здоровья, маны и скорости, вид оружия, параметры дальнего боя |
| `projectiles.ts` | Стрелы и магические заряды в полёте |
| `dev.ts` | Быстрые действия для тестирования (только в мирах, созданных для разработки) |
| `progression.ts` | Кривая опыта, рост героя и монстров по уровням, начисление опыта, штраф за смерть |
| `skills.ts` | Каталог умений (уровень, мана, откат, эффект) и их применение |
| `items.ts` | Каталог предметов (ID, вид, слот, грейд, числа) и таблица добычи |
| `inventory.ts` | Сумка, экипировка, монеты, подбор и выбрасывание, урон и защита героя, зелья и заряды |
| `npcs.ts` | Жители: кто что продаёт, покупка и продажа, обучение умениям, стражники |
| `enchant.ts` | Закалка предметов свитками и разбор на кристаллы |
| `crafting.ts` | Рецепты, изучение рецептов и изготовление у кузнеца |
| `travel.ts` | Проходы между картами |

Ключевые решения:

- **Фиксированный шаг.** Мир движется тиками по 50 мс (`TICK_MS`). Результат не зависит
  от частоты кадров устройства.
- **Детерминизм.** `createWorld(seed)` и последовательность команд полностью определяют
  результат. Поэтому в `sim` запрещены `Math.random`, `Date` и любые обращения к браузеру.
  Это проверяет тест «replays identically» и сборка `tsconfig.sim.json` без DOM.
- **Команды.** Единственный способ изменить мир извне — `step(world, commands)`. Команды:
  `moveTo` (идти в точку, обходя стены), `moveDir` (идти в направлении, пока оно зажато;
  нулевой вектор — остановка), `attack` (удар в направлении), `respawn` (возродиться;
  работает только когда герой мёртв), `skill` (применить умение в направлении; нулевое
  направление — куда смотрит герой), `use` (выпить зелье), `toggleCharges` (включить или
  выключить заряды), `buy` / `sell` (торговля рядом с торговцем), `learn` (выучить умение у наставника),
  `enchant` / `crystallize` (закалить предмет или разбить на кристаллы у кузнеца),
  `craft` (изготовить по рецепту у кузнеца), `travel` (уйти через выход, у которого
  стоит герой), `equip` / `unequip` / `drop` (надеть из ячейки
  сумки, снять из слота, выбросить ячейку). Команды движения отменяют друг друга. Мёртвый герой
  не принимает ничего, кроме `respawn`. Невозможные команды
  (стена, точка вне карты, не число) игнорируются; направление нормализуется в правилах,
  поэтому никакой ввод не даёт скорость выше `PLAYER_SPEED`.
- **Свободное перемещение.** Герой — круг радиусом `PLAYER_RADIUS` (0,3 тайла) с дробными
  координатами, к сетке не привязан. Стены остаются тайлами. При движении в стену круг
  выталкивается наружу, поэтому герой скользит вдоль стены, а не застревает.
- **Маршрут по клику.** Сетка используется только чтобы найти обход стен. Затем лишние
  точки выбрасываются (до каждой следующей герой идёт по прямой, если она свободна), а
  конечная точка — ровно место клика, отодвинутое от стены, если герой там не помещается.

- **События.** За каждый тик правила складывают в `world.events` то, что произошло:
  `playerSwing`, `monsterHit`, `monsterWindup`, `playerHit`, `playerDied`,
  `playerRespawned`, `lootDropped`, `itemPicked`, `inventoryFull`, `xpGained`, `levelUp`,
  `skillUsed`, `skillDenied`, `playerHealed`, `itemUsed`, `useDenied`, `chargesEmpty`,
  `bought`, `sold`, `tradeDenied`, `travel`, `skillLearned`, `learnDenied`, `enchanted`,
  `enchantFailed`, `enchantDenied`, `crystallized`, `crystallizeDenied`, `guardStrike`,
  `recipeLearned`, `recipeDenied`, `crafted`, `craftFailed`, `craftDenied`. В событиях только ID и числа. Клиент превращает их в анимацию и
  цифры урона; сам он исход боя не считает.
- **Случайность в бою.** Броски урона идут из `world.rngState`, который сохраняется в
  сейве: перезагрузка страницы не даёт «перебросить» результат.

#### Карты и регионы

- Карт две (`world.zone`): `overworld` — открытый мир 100×60 клеток, и `dungeon` —
  подземелье 24×24. `World` — это одна карта.
- **Открытый мир** всегда строится из `WORLD_SEED`, поэтому география у всех одинакова.
  Деревня задана рисунком из символов и вставлена в карту; вокруг — случайные деревья,
  дорога по ряду `ROAD_ROW` от ворот до входа в копи и полоса леса по столбцу
  `HOLLOW_BORDER` с проходами. Недостижимый пол превращается в стены.
- **Регион** — именованная часть карты (`REGIONS`): безопасен ли, диапазон уровней и вид
  монстров. `regionAt(zone, pos)` говорит, в каком регионе точка. Границы регионов —
  это только правило; стен между ними нет, кроме полосы леса.
- **Уровень монстра** хранится в самом монстре (`monster.level`). В открытом мире он
  случайный в диапазоне региона и от героя не зависит; в подземелье равен
  `world.dungeonLevel` (`minesLevelFor(уровень героя)`, не ниже `MINES_MIN_LEVEL`).
- **Безопасный регион.** Монстры не преследуют героя, пока он в деревне, а здоровье и
  мана восстанавливаются по единице каждые `SAFE_REGEN_INTERVAL`.
- **Поводок.** В открытом мире монстр, ушедший от своего места дальше `MONSTER_LEASH`,
  бросает погоню (`returning`), идёт домой, не реагируя на героя (кроме удара по нему),
  и по приходе полностью лечится.
- **Возрождение.** Убитый монстр открытого мира попадает в `world.respawns` и через
  `MONSTER_RESPAWN_TIME` появляется на своём месте, если герой не стоит ближе
  `MONSTER_RESPAWN_CLEARANCE`. В подземелье убитые остаются убитыми.
- **Вход и выход из подземелья.** Команда `travel` у прохода (радиус `EXIT_RANGE`)
  только сообщает событием `travel`, куда герой уходит. Новую карту строит клиент:
  `travelerOf(world)` переносит героя с текущими здоровьем и маной. Выйдя из копей,
  герой появляется у входа в них, а не в деревне.
- **Виды монстров** — `MONSTER_KINDS` в `balance.ts`: множители здоровья, урона и опыта
  и собственная скорость.
- **Поиск пути** — A* с кучей. У монстров бюджет 500 клеток на поиск, чтобы герой за
  длинной стеной не заставлял каждого из них обыскивать весь мир.

#### Бой

Все числа — в `balance.ts`.

- **Удар героя.** Команда `attack` с направлением. Удар приземляется через короткую
  задержку (`PLAYER_ATTACK_WINDUP`) и задевает всех монстров в секторе
  (`PLAYER_ATTACK_ARC`, `PLAYER_ATTACK_RANGE`), до которых есть прямая линия без стен.
  Следующий удар возможен после `PLAYER_ATTACK_COOLDOWN`, сколько бы команд ни пришло.
  Попадание отбрасывает монстра и прерывает его замах.
- **Монстры.** Стоят на месте, пока герой не подойдёт на `MONSTER_AGGRO_RANGE` или не
  ударит. Затем идут к герою: по прямой, если она свободна, иначе — в обход стен по
  тайлам. Вблизи начинают замах (`MONSTER_ATTACK_WINDUP`, событие `monsterWindup`), во
  время которого стоят. Если к концу замаха герой отошёл дальше `MONSTER_ATTACK_REACH`,
  удар не попадает. Монстры не входят друг в друга, в героя и в стены.
- **Здоровье.** Восстанавливается само, если `PLAYER_REGEN_DELAY` не было урона.
- **Смерть.** При нуле здоровья герой останавливается. По команде `respawn` в открытом
  мире герой переносится в деревню с полным здоровьем; из подземелья его переносит туда
  клиент, построив карту открытого мира заново.

Зачем так: правила тестируются без браузера, а если позже понадобится сервер (облачные
сохранения, рейтинги), он сможет запускать тот же код и перепроверять результат.

#### Расы, классы и дальний бой

- Раса и класс лежат в `player.race` и `player.cls` и задаются при создании героя
  (`newHero`). `RACES` и `CLASSES` — множители к таблицам уровней; базой служит
  человек-воин, поэтому `heroMaxHp` и `heroMaxMp` для него равны табличным.
- **Вид оружия** (`weaponType`: `sword`, `bow`, `staff`) есть у каждого оружия; класс
  может надеть только свой (`equipDenied`).
- **Удар** зависит от оружия в руке. Меч или пустые руки — удар по сектору. Лук или
  посох — снаряд: `fire()` кладёт его в `world.projectiles`, `updateProjectiles` каждый
  тик двигает мелкими шагами, останавливает о стену, бьёт первого монстра на пути
  (пробивающий — всех по одному разу) и снимает по исчерпании дальности.
- **Попадание по монстру** всегда идёт через `hitMonster` (урон оружия × бонус уровня ×
  множитель, отбрасывание, сбитый замах, добыча, опыт) — для удара, снаряда и умений по
  площади (`hitMonstersAround`).
- **Умения** имеют класс (`SKILLS[id].cls`); `classSkills(cls)` даёт три умения класса в
  порядке клавиш. Виды эффекта: `strike`, `shot` (число снарядов, веер, пробитие, взрыв),
  `nova` (удар вокруг с замедлением), `heal`, `haste`.

#### Уровни, мана и умения

- **Опыт.** За убитого монстра — `monsterXp(dungeonLevel)`. До следующего уровня нужно
  `xpToNextLevel(level)` = `XP_CURVE_BASE × level ^ XP_CURVE_POWER`. `player.xp` хранит
  опыт внутри текущего уровня. Потолок — `MAX_LEVEL`.
- **Рост героя.** Максимум здоровья и маны и множитель урона оружия считаются от уровня
  (`maxHpAtLevel`, `maxMpAtLevel`, `damageBonusAtLevel`). При новом уровне здоровье и
  мана восстанавливаются. Распределяемых очков нет.
- **Уровень подземелья** (`world.dungeonLevel`) задаётся при создании и по умолчанию
  равен уровню героя. От него зависят здоровье, урон и опыт монстров.
- **Смерть** отнимает `DEATH_XP_LOSS` от опыта, нужного для уровня, но не больше, чем
  есть; уровень не падает. Потеря приходит в событии `playerDied`.
- **Мана** восстанавливается по одной единице раз в `PLAYER_MP_REGEN_INTERVAL`.
- **Умения** описаны в `SKILLS` (`skills.ts`): уровень открытия, цена, откат и эффект —
  `strike` (удар со своей шириной, дальностью и множителем урона) или `heal`. Удар
  умения идёт тем же путём, что обычный (`PendingAttack` → `resolvePlayerAttack`).
  Отказ (не тот уровень, нет маны, откат) ничего не тратит и приходит событием
  `skillDenied` с причиной.

#### Жители

- `world.npcs` — список жителей карты: вид (`alchemist`, `outfitter`, `blacksmith`,
  `trainer`, `guard`) и место. Они заданы буквами на рисунке деревни в `zones.ts`; в
  подземелье их нет. Жители не мешают ходить, монстры их не трогают.
- Говорить можно с ближайшим жителем в радиусе `NPC_RANGE` (`nearestNpc`).
- **Торговцы.** `SHOP_STOCK` говорит, что продаёт каждый; купить у алхимика товар
  оружейника нельзя (`tradeDenied: notSold`). Продать из сумки можно любому из них.
- **Наставник.** `learn` требует стоять рядом, иметь уровень умения и `SKILL_PRICE`
  монет. Выученные умения лежат в `player.skills`; без этого `skill` отвечает отказом
  `unlearned`, даже если уровень позволяет.
- **Стражники.** Раз в `GUARD_COOLDOWN` стражник бьёт монстра в радиусе `GUARD_RANGE` на
  долю `GUARD_DAMAGE_SHARE` его полного здоровья. Убитый так монстр не даёт ни опыта, ни
  добычи и возрождается как обычно.

#### Закалка

- Уровень закалки — свойство экземпляра: у надетого он в `player.equipmentEnchant[слот]`,
  у предмета в сумке и на полу — в поле `enchant` (отсутствует, когда ноль). Надевание,
  снятие, выбрасывание и подбор его сохраняют.
- `enchant` у кузнеца тратит свиток, подходящий по грейду и виду (`scrollFor`). До
  `ENCHANT_SAFE` успех гарантирован; выше — шанс `ENCHANT_CHANCE`, бросок идёт из
  `world.rngState`. При неудаче предмет исчезает и превращается в кристаллы
  (`crystalsFor`; у предметов без грейда — ноль). Потолок — `ENCHANT_MAX`.
- Прибавка от закалки (`enchantBonus`) входит в `playerDamage` и `playerDefense`.
- `crystallize` разбивает на кристаллы предмет из сумки (только с грейдом). Кристаллы
  стоят меньше, чем продажа предмета: это выбор ради будущего крафта, а не способ
  заработать.

#### Крафт

- Рецепты — `RECIPES` в `crafting.ts`: что получается и сколько, ингредиенты, шанс и
  нужно ли рецепт сначала изучить (`mustLearn`). Заготовки и заряды умеет любой кузнец;
  экипировку грейда D — только по изученному рецепту.
- **Изучение.** Предмет вида `recipe` применяется командой `use`: рецепт попадает в
  `player.recipes`, предмет тратится. Уже известный рецепт не тратит предмет.
- **Изготовление.** `craft` требует стоять у кузнеца, знать рецепт, иметь все
  ингредиенты и место в сумке под результат — всё это проверяется до того, как что-то
  потрачено. Затем ингредиенты тратятся, и бросок из `world.rngState` решает исход.
- **Экономика.** Тест проверяет, что ни один рецепт не даёт прибыли при покупке всех
  ингредиентов и продаже результата. Меняя цены или составы, запускайте `npm test`.

#### Инструменты разработчика

- Мир, созданный с `dev: true`, принимает команду `dev`: `levelUp`, `coins`, `kit`
  (материалы, кристаллы, свитки, зелья), `heal`, `clear` (убрать монстров рядом),
  `teleport`. В обычном мире команда игнорируется.
- В клиенте это включается константой `DEV_TOOLS` в `main.ts` (сейчас `true`): кнопка
  DEV открывает панель, там же «Удалить героя и создать нового». Перед выпуском игры
  для игроков константу нужно выключить.

#### Предметы и добыча

- **Каталог** — `ITEMS` в `items.ts`. Виды: `currency` (монеты, идут в кошелёк),
  `material` (складываются в стопки), `consumable` (зелья и заряды; эффект `heal`,
  `mana` или `charge`), `scroll` (свиток закалки: для оружия или доспехов, по грейду),
  `recipe` (учит рецепту),
  `equipment` (слот, грейд, урон или защита). У всего, кроме монет,
  есть цена `price`.
  Экземпляр предмета — это просто его ID: случайных свойств нет.
- **Добыча.** У каждого вида монстра своя таблица `DROP_TABLES` в `items.ts`: монеты и
  строки «шанс — предметы — количество». Окно охотника читает эти же таблицы, поэтому
  не может разойтись с правилами. При смерти монстра на пол падают монеты и, по одному
  броску, не более одного из перечисленного в его таблице. Раньше таблица была одна на всех: материал, обычная экипировка, экипировка грейда D, зелье, пачка зарядов,
  свиток закалки, рецепт. Шансы — в
  `items.ts`. Стартовое оружие не выпадает.
- **Подбор.** Герой забирает всё в радиусе `LOOT_PICKUP_RADIUS`. Если сумка полна,
  предмет остаётся лежать, приходит одно событие `inventoryFull`, и повторная попытка
  будет, когда герой отойдёт и вернётся. Так же устроено выбрасывание: предмет не
  прыгает обратно в сумку, пока герой не отойдёт.
- **Числа героя.** Урон — от оружия (`playerDamage`), без оружия — `UNARMED_DAMAGE`.
  Защита — сумма защиты надетого (`playerDefense`); из урона монстра она вычитается, но
  удар наносит не меньше `MIN_DAMAGE_TAKEN`.
- **Заряды.** Пока `player.chargesOn`, каждый начатый удар (обычный или умением) тратит
  один заряд, подходящий по грейду к оружию в руке (`CHARGE_FOR_GRADE`), и умножает урон
  на `CHARGE_DAMAGE_MULTIPLIER`. Нет подходящего заряда — режим выключается, приходит
  событие `chargesEmpty`. Без оружия заряды не работают.
- **Зелья.** `use` тратит одно зелье из сумки и запускает общий откат `POTION_COOLDOWN`.
  Отказ (нет зелья, откат, здоровье или мана уже полные) ничего не тратит и приходит
  событием `useDenied`.
- **Вход и выход из подземелья** сохраняют уровень, монеты, сумку и экипировку. Лежащее
  на полу остаётся на покинутой карте и пропадает.
- **`player.revision`** растёт при любом изменении монет, сумки или экипировки; по нему
  клиент понимает, что панель пора перерисовать.

**Инвентарь.** Ячейки сетки создаются один раз, дальше меняется только их содержимое:
если пересоздавать кнопку между нажатием и отпусканием мыши, щелчок теряется (так
терялись покупки у торговца). Подсказка — один общий элемент, который ставится рядом с
ячейкой и не выходит за экран. Полное описание предмета продублировано в `aria-label`
ячейки. Выбор сбрасывается, если после действия в ячейке оказался другой предмет.

**Сохранение при изменении вещей.** Сцена следит за `player.revision` и сохраняет игру
сразу, как только изменились монеты, сумка или экипировка.

**Чёткость.** Холст в `RENDER_SCALE` раз больше окна (по плотности пикселей экрана, не
больше 2) и показывается уменьшенным; зум камеры умножается на тот же коэффициент.
Картинки препятствий рисуются вдвое крупнее показываемого размера (`TEXTURE_SCALE`).

**Цель.** Сцена считает целью монстра под курсором, а если такого нет — того, по кому
герой попал последним (помнит `TARGET_MEMORY_MS`). Под целью рисуется красное кольцо, а
в интерфейс уходит событие `onTarget` с монстром или `null`.

**Отрисовка карты.** Земля запекается в несколько больших картинок (по 20×20 клеток), а
каждый вид препятствия (дерево трёх размеров, каменный блок, частокол, дом) рисуется один
раз в маленькую картинку и затем просто расставляется по клеткам. Рисовать тысячи клеток
фигурами на каждом кадре было бы слишком медленно: на карте 100×60 запечённый вариант
работает быстрее, чем прежняя комната 34×34 без запекания.

Сцена рисует положение героя между двумя последними тиками (интерполяция), поэтому
движение плавное при любой частоте кадров. Время между кадрами берётся из
`performance.now()`, а не из Phaser: тот сглаживает и обрезает свою дельту, и на
устройствах с неровной частотой кадров игра шла медленнее.

Управление:

| Ввод | Действие |
|---|---|
| WASD или стрелки | Идти в направлении на экране, пока клавиша зажата |
| Левая кнопка мыши (можно удерживать) | Удар в сторону курсора |
| Пробел (можно удерживать) | Удар по ближайшему монстру рядом, иначе — куда смотрит герой |
| Правая кнопка мыши (можно удерживать) | Идти в точку, за курсором |
| Q, E, R (или щелчок по кнопке умения) | Умения. С клавиши — в сторону курсора, по щелчку — в ближайшего монстра |
| 1, 2 | Выпить зелье исцеления, зелье маны |
| F | Включить или выключить заряды оружия |
| T | Взаимодействие с тем, что рядом: житель — поговорить (лавка, наставник, кузница, реплика стражника), светящийся проход — войти в копи или выйти из них. Повторное T закрывает окно |
| I | Открыть или закрыть инвентарь |
| Наведение на ячейку инвентаря или панели | Подсказка о предмете или умении |
| Наведение курсора на монстра | Монстр становится целью: имя, уровень и здоровье в рамке сверху |
| Щелчок / двойной щелчок по ячейке | Выбрать предмет / сразу надеть, снять или выпить |

Клавиши читаются по физическому положению (`KeyboardEvent.code`), раскладка не важна.
Игра при открытом инвентаре не останавливается. Пока открыто окно разговора (торговец, наставник,
кузнец), герой не атакует (ходить можно). Нажатия мыши по панелям и кнопкам интерфейса в игру не
попадают: Phaser слышит мышь во всём окне, поэтому сцена проверяет, что нажатие началось
на холсте (`pointer.downElement`). Автоприцел для пробела
считается в клиенте: это удобство ввода, правилам всё равно приходит обычная команда
`attack` с направлением.

### Сохранение

- Хранится в `localStorage` браузера, на этом устройстве. Ключи: `isometry-rpg.save`,
  `isometry-rpg.locale`.
- Формат (версия 11): `{ version, race, cls, zone, seed, x, y, distance, hp, dead,
  rngState, level, xp, mp, dungeonLevel, chargesOn, coins, inventory, equipment, enchants,
  skills, recipes, loot }`. `dead` — ID убитых монстров подземелья, `loot` — предметы на
  полу. Откаты умений и снаряды в полёте не сохраняются.
- Сохраняется, когда герой остановился, убил монстра, изменились монеты, сумка или
  экипировка, герой погиб или возродился, и при закрытии страницы.
- Сейв считается недоверенным вводом: каждое поле проверяется (раса и класс, уровень и
  опыт, известные ID, размер стопок, вместимость сумки, оружие своего класса, умения
  своего класса). Повреждённый сейв не ломает игру — показывается создание героя.
- **Старые сохранения не переносятся.** Пока игра в разработке, сейв версии ниже текущей
  считается устаревшим: игрок видит сообщение и создаёт нового героя. Когда появятся
  настоящие игроки, вместо этого нужно писать миграции.

### Что видит игрок при сбоях

| Ситуация | Поведение |
|---|---|
| Сейв не читается или устарел | Экран создания героя и уведомление |
| Браузер запретил хранилище или оно переполнено | Игра работает, в HUD предупреждение, что прогресс не сохранится |
| Необработанная ошибка в коде | Экран «Что-то пошло не так» с кнопкой перезагрузки; детали в консоли |
| Отключён JavaScript | Статичное сообщение на двух языках |

## Как расширять

- **Новое правило** (лут, опыт, умение): состояние — в `World`, логика — в `step()` или
  в функции, которую он вызывает, новая команда — в тип `Command`, новое событие — в
  `GameEvent`, числа — в `balance.ts`. Сначала тест в `tests/`.
- **Новый рецепт**: ID в `RecipeId`, запись в `RECIPES`. Если его надо изучать — предмет
  вида `recipe` в `items.ts` (с ID в `RecipeItemId` в `itemText.ts` и иконкой) и строка в
  ассортименте кузнеца.
- **Новый житель**: вид в `NpcKind`, буква в рисунке деревни и в `VILLAGE_PEOPLE`
  (`zones.ts`), название и цвета в `npcText.ts`, что происходит по T — в `interact()` в
  `main.ts`. Торговцу — список в `SHOP_STOCK`.
- **Новое умение**: цена в `SKILL_PRICE`, ID в `SkillId` и `SKILL_IDS`, запись в `SKILLS`, начальный откат в
  `createWorld`, тексты и клавиша в `skillText.ts`. Новый вид эффекта — в `SkillEffect`
  и `useSkill`.
- **Новый предмет**: ID в `ItemId` и запись в `ITEMS` (`items.ts`), название в
  `en.json` / `ru.json`, строка в `ITEM_NAME` (`itemText.ts`) и иконка в `ICONS`
  (`itemIcon.ts`) — без них проект не соберётся. Попадёт в добычу сам, если это материал или экипировка. Чтобы торговец его продавал —
  добавить в его список в `SHOP_STOCK`.
- **Новый вид монстра**: ID в `MonsterKind` и строка в `MONSTER_KINDS` (`balance.ts`),
  таблица в `DROP_TABLES`, место обитания в `HABITAT` (`hunterPanel.ts`), имя,
  внешний вид — в `drawMonsterBody` по этому ID.
- **Новый регион открытого мира**: ID в `RegionId`, запись в `REGIONS`, правило в
  `regionAt`, число и расстановка монстров в `buildOverworld`, название и палитра в
  `zoneText.ts`. Если карта растёт — `WORLD_WIDTH` / `WORLD_HEIGHT`.
- **Новое подземелье** сейчас потребует доработки: `ZoneKind` знает одно `dungeon`.
- **Новый объект на экране**: рисуется в `DungeonScene` по данным из `World`.
  Глубина отрисовки — `x + y` в координатах мира.
- **Новый текст**: см. `LOCALIZATION.md`.
- **Новые данные в сейве**: поле в `SaveData`, проверка в `parseSave`, тест, новая версия.

## Известные ограничения

- Открытый мир 100×60 клеток с тремя регионами и одно подземелье 24×24; три вида
  монстров, 38 предметов двух грейдов, три класса по три умения.
- Баланс не настроен: числа классов, умений и добычи выставлены на глаз.
- Броня общая для всех классов; у классов различается только оружие.
- Экипировку грейда D никто не продаёт, только заряды и свитки к ней.
- Над жителями и монстрами нет подписей: житель опознаётся по одежде, значку и
  подсказке рядом, монстр — по рамке цели. Стражники не двигаются и говорят одну реплику.
- Большой карты мира нет. Окна интерфейса нельзя перетаскивать.
- Копи создаются заново при каждом входе. Добыча у всех монстров одинакова.
- Добыча не зависит от уровня монстра: на высоких уровнях падает то же, что на первом.
- Телефоны не поддерживаются: касанием можно только ходить, атаковать нечем.
- Наказания за смерть нет. Баланс чисел предварительный.
- Звука нет.
- Графика временная (фигуры), на экранах с высокой плотностью пикселей слегка размыта.
- Сейв привязан к браузеру и устройству; очистка данных сайта его удаляет.
- У превью каждой ветки общий `localStorage` с основной версией (один домен), поэтому
  сейвы разных веток перезаписывают друг друга.
- Phaser даёт ~330 КБ (gzip) на первую загрузку.
