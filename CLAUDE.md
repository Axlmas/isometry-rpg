# Isometry RPG — инструкции для Claude

Этот файл Claude читает в начале каждой сессии. Здесь правила работы над проектом.
Дизайн игры (что строим) лежит отдельно, в `docs/GDD.md`.

## Контекст

- Изометрическая RPG. Делаем в режиме вайбкодинга: владелец проекта ставит задачи и
  проверяет результат, код пишет Claude.
- Владелец не разработчик, но знает SQL и Python. Технические решения объясняй коротко
  и по делу. Если есть развилка, предложи вариант и скажи, почему выбрал его.
- Общение — на русском. Код, комментарии в коде, коммиты и названия веток — на английском.

## Стек

- Пока не выбран окончательно, решим после первых инструкций в `docs/GDD.md`.
- По умолчанию: браузерная игра (TypeScript + Vite), чтобы она открывалась по ссылке
  с телефона и ПК без установки.

## Как работаем

- `main` — всегда рабочая версия, она живёт по адресу https://axlmas.github.io/isometry-rpg/
- Одна задача = одна ветка = одна сессия = один PR в `main`. Владелец играет в превью и
  сливает PR, если всё нравится.
- У каждой ветки есть превью: `https://axlmas.github.io/isometry-rpg/preview/<slug>/`, где
  `<slug>` — имя ветки в нижнем регистре, `/` и прочие символы заменены на `-`
  (`claude/add-map` → `claude-add-map`). Список всех превью: `/preview/`.
- В описании PR всегда давай ссылку на превью. Обновление превью занимает 1–2 минуты
  после push. Перед тем как отдать PR, открой превью и убедись, что игра запускается.
- Маленькие осмысленные коммиты. Приложи к PR скриншот, если менялось что-то видимое.
- Не добавляй тяжёлые зависимости без причины. Ассеты — только свои или со свободной
  лицензией, источник указывай в `docs/ASSETS.md`.

## Деплой

- `.github/workflows/deploy.yml` при каждом изменении любой ветки пересобирает весь сайт
  скриптом `.github/scripts/build-site.sh`: `main` кладёт в корень, остальные ветки —
  в `preview/<slug>/`, затем деплоит всё одним артефактом.
- Push в ветку, отличную от `main`, запускает `preview-trigger.yml`, а тот через
  `workflow_run` запускает деплой. Так сделано, потому что публиковать на Pages разрешено
  только из контекста `main`. Удалённая ветка исчезает из превью при следующем деплое.
- Сборка ветки: если есть `package.json`, выполняются `npm ci` и `npm run build`, публикуется
  `dist/`. Если `package.json` нет, публикуется `index.html` из корня.
- Игра открывается по разным путям (корень и превью), поэтому пути к ресурсам должны быть
  относительными. В Vite: `base: './'`. Имя ветки доступно при сборке как
  `import.meta.env.VITE_BRANCH`.
- Если сборка `main` падает, деплой отменяется и остаётся предыдущая версия. Если падает
  сборка другой ветки, на её превью появляется страница «сборка не прошла».
